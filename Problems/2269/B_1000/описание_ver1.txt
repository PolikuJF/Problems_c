ОПИСАНИЕ ЗАДАЧИ
----------------------------------------
Дано a тестов. В каждом тесте:
  - Считывается b чисел.
  - Для каждого числа вычисляется его "судьба"
    при многократном применении операции:
        заменить число суммой квадратов его цифр.
  - Нужно посчитать количество пар чисел, которые
    приведут к одинаковому финальному состоянию
    за одинаковое количество шагов (с учётом
    периодичности для "несчастливых" чисел).

Финальные состояния:
  - 1 — "счастливое" число (приходит к 1)
  - 4 — "несчастливое" число (попадает в цикл 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4)

ИДЕЯ РЕШЕНИЯ
----------------------------------------
1. Для каждого числа вычисляем:
   - конечное состояние (1 или 4)
   - количество шагов до его достижения

2. Числа, приходящие к 1, все эквивалентны друг другу —
   любые два таких числа образуют подходящую пару.
   Количество пар = C(group_size, 2) = n*(n-1)/2.

3. Числа, приходящие к 4, попадают в цикл длины 8.
   Два числа эквивалентны, если их количество шагов
   совпадает по модулю 8 (то есть они находятся
   в одной фазе цикла).
   Для каждой группы с одинаковым остатком mod 8
   считаем C(group_size, 2).

4. Суммируем все пары по всем группам.

ПОЧЕМУ ЦИКЛ ДЛИНЫ 8
----------------------------------------
Последовательность для "несчастливых" чисел:
  4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → ...
Длина цикла = 8. Поэтому два числа с шагами s1 и s2
эквивалентны, если s1 ≡ s2 (mod 8).

РАЗБОР КОДА
----------------------------------------

1) Функция count_operations(num)
   std::pair<int, int> count_operations(int num) {
       int steps = 0;
       while (num != 1 && num != 4) {
           int sum = 0;
           int t = num;
           while (t > 0) {
               int d = t % 10;
               sum += d * d;
               t /= 10;
           }
           num = sum;
           ++steps;
       }
       return {num, steps};
   }

   - Пока число не равно 1 или 4:
       * Считаем сумму квадратов цифр.
       * Заменяем число на эту сумму.
       * Увеличиваем счётчик шагов.
   - Возвращаем пару: (конечное состояние, шаги).

   Почему останавливаемся на 4, а не на всей
   последовательности цикла? Потому что 4 — это
   первое число, которое встречается при входе
   в цикл, и его достаточно для идентификации
   "несчастливого" числа.

2) main() — чтение и обработка
   int a;  std::cin >> a;
   for (int i = 0; i < a; ++i) {
       int b;  std::cin >> b;
       std::vector<std::pair<int,int>> data(b);
       for (int j = 0; j < b; ++j) {
           int x;  std::cin >> x;
           data[j] = count_operations(x);
       }
       std::sort(data.begin(), data.end());
       ...
   }

   - Считываем количество тестов a.
   - Для каждого теста считываем b чисел.
   - Для каждого числа вызываем count_operations
     и сохраняем результат в vector.
   - Сортируем vector пар — это группирует
     одинаковые состояния рядом.

3) Подсчёт пар
   int j = 0;
   while (j < b) {
       int k = j;
       int state = data[j].first;

       if (state == 1) {
           // все числа с состоянием 1 эквивалентны
           while (k < b && data[k].first == 1) ++k;
           long long group_size = k - j;
           total += group_size * (group_size - 1) / 2;
       } else {
           // состояние 4 — нужно учитывать шаги mod 8
           while (k < b && data[k].first == 4) ++k;

           std::vector<int> norm;
           for (int t = j; t < k; ++t) {
               int s = data[t].second;
               while (s >= 8) s -= 8;
               norm.push_back(s);
           }

           std::sort(norm.begin(), norm.end());

           int m = 0;
           while (m < (int)norm.size()) {
               int p = m;
               while (p < (int)norm.size() && norm[p] == norm[m]) ++p;
               long long group_size = p - m;
               total += group_size * (group_size - 1) / 2;
               m = p;
           }
       }
       j = k;
   }

   - Идём по отсортированному массиву.
   - Если состояние == 1: считаем все подряд
     и добавляем C(n, 2).
   - Если состояние == 4: приводим шаги к диапазону
     [0, 7] (вычитаем 8, пока не станет меньше 8),
     сортируем и считаем группы с одинаковым остатком.
   - Суммируем все пары.

4) Формула C(n, 2)
   total += group_size * (group_size - 1) / 2;
   Количество способов выбрать 2 элемента из группы
   размера n. Именно столько пар можно составить.

СЛОЖНОСТЬ
----------------------------------------
Для одного теста с b числами:
  - Вычисление count_operations: O(log num) на число
  - Сортировка: O(b log b)
  - Подсчёт пар: O(b)
Итого: O(b log b) на тест.
Память: O(b) — храним массив пар.

  6^2 + 8^2 = 36 + 64 = 100
  1^2 + 0^2 + 0^2 = 1
  → состояние 1, шагов 4

Число 28:
  2^2 + 8^2 = 4 + 64 = 68
  6^2 + 8^2 = 36 + 64 = 100
  1^2 + 0^2 + 0^2 = 1
  → состояние 1, шагов 3

Число 1:
  → состояние 1, шагов 0

Число 4:
  → состояние 4, шагов 0

  (1, 0), (1, 3), (1, 4), (4, 0)

Группа state=1: размер 3 → C(3,2) = 3 пары

ЗАМЕТКИ И ВОЗМОЖНЫЕ ПРОБЛЕМЫ
----------------------------------------
1. Приведение шагов к mod 8 через while (s >= 8) s -= 8
   работает, но медленнее, чем s % 8. Можно заменить на:
       norm.push_back(s % 8);
   Это то же самое, но быстрее.

2. Если число уже равно 1 или 4 изначально,
   steps = 0. Это корректно.

3. Для очень больших чисел (например, 10^9)
   количество шагов невелико (не более ~20),
   поэтому переполнения нет.

4. long long total используется, потому что
   количество пар может быть большим:
   при b = 10^5 максимальное total ~ 5 * 10^9,
   что не влезает в int.

5. Алгоритм корректно обрабатывает случай,
   когда все числа "счастливые" или все
   "несчастливые".

ЗАМЕТКИ ПО ОПТИМИЗАЦИИ
----------------------------------------
- Можно заменить while (s >= 8) s -= 8 на s % 8.
- Можно использовать unordered_map вместо
  сортировки, но сортировка проще и надёжнее.
- Для повторяющихся чисел можно кэшировать
  результаты count_operations в map.
