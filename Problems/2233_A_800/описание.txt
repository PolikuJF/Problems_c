========================================
Описание программы
========================================

Задача: A. Разработка ИИ-проекта

Назначение:
Программа обрабатывает t тестов. В каждом тесте заданы
четыре целых числа n, x, y, z:
  - n — объём проекта в строках кода
  - x — скорость Максима (строк в час)
  - y — скорость Никиты без ИИ (строк в час)
  - z — время настройки ИИ (в часах)

Никита может выбрать один из двух вариантов:
  1. Не использовать ИИ и сразу писать со скоростью y.
  2. Сначала потратить z часов на настройку ИИ (в это время
     он не пишет код), а затем писать со скоростью 10 * y.

Максим пишет всё время со скоростью x, начиная с самого начала.
Проект считается завершённым, как только суммарно написано
не менее n строк. Время измеряется целыми часами: если проект
завершается в середине часа, этот час засчитывается полностью.

Нужно найти минимальное количество полных часов, после которого
проект будет завершён, при оптимальном выборе Никиты.

Алгоритм работы:
1. Считать количество тестов t.
2. Для каждого теста:
   а) Считать n, x, y, z.
   б) Вычислить время без ИИ:
          count1 = ceil(n / (x + y))
      Здесь x + y — суммарная скорость Максима и Никиты.
   в) Вычислить время с ИИ:
          count2 = ceil((n + 10 * y * z) / (x + 10 * y))
      Пояснение: за z часов настройки Максим напишет x * z строк,
      а Никита — 0. Чтобы компенсировать это, к общему объёму
      добавляется 10 * y * z (как если бы Никита писал
      со скоростью 10 * y в течение z часов).
      После настройки суммарная скорость = x + 10 * y.
   г) Вывести min(count1, count2).
3. Завершить работу.

Пояснение формул:
Формула для count1:
  Общая скорость = x + y.
  Время = n / (x + y), округлённое вверх.

Формула для count2:
  Первые z часов: Максим пишет x * z строк, Никита — 0.
  Остаток работы: n - x * z.
  После настройки скорость = x + 10 * y.
  Время после настройки = (n - x * z) / (x + 10 * y).
  Общее время = z + (n - x * z) / (x + 10 * y).
  
  Преобразование:
    z + (n - x * z) / (x + 10 * y)
    = (z * (x + 10 * y) + n - x * z) / (x + 10 * y)
    = (n + 10 * y * z) / (x + 10 * y)
  
  Именно это и вычисляется в count2, но без явного
  прибавления z — оно уже учтено в числителе.

Разбор кода:
1. Подключение библиотек:
   - iostream — ввод-вывод
   - cmath — функция ceil

2. Ускорение ввода-вывода:
   ios_base::sync_with_stdio(false);
   cin.tie(nullptr);

3. Основной цикл while(t--):
   - Считываются n, x, y, z (тип long long).
   - Вычисляется count1:
        ceil((double)n / (x + y))
   - Вычисляется count2:
        ceil((double)(n + 10 * y * z) / (x + 10 * y))
   - Выводится минимум из двух значений.

4. Приведение к double перед делением необходимо,
   чтобы ceil работал корректно с дробными числами.

Сложность:
Время:  O(t) — один проход по всем тестам.
Память: O(1) — дополнительные структуры не используются.

Пример работы:
Вход:
3
10 2 3 1
100 5 5 10
7 1 1 1

Тест 1: n=10, x=2, y=3, z=1
  count1 = ceil(10 / 5) = 2
  count2 = ceil((10 + 10*3*1) / (2 + 30)) = ceil(40 / 32) = 2
  min = 2

Тест 2: n=100, x=5, y=5, z=10
  count1 = ceil(100 / 10) = 10
  count2 = ceil((100 + 10*5*10) / (5 + 50)) = ceil(600 / 55) = 11
  min = 10

Тест 3: n=7, x=1, y=1, z=1
  count1 = ceil(7 / 2) = 4
  count2 = ceil((7 + 10*1*1) / (1 + 10)) = ceil(17 / 11) = 2
  min = 2

Выход:
2
10
2

Заметки:
- Тип long long используется, чтобы избежать переполнения
  при больших значениях n, x, y, z (до 10^4 каждое).
  Произведение 10 * y * z может достигать 10^9, что
  выходит за пределы int (2 * 10^9), но long long
  справляется.
- Функция ceil возвращает double, поэтому результат
  приводится к long long явно.
- При больших значениях возможна потеря точности
  из-за double. Альтернатива — целочисленное округление
  вверх: (a + b - 1) / b.
  Например:
      count1 = (n + (x + y) - 1) / (x + y);
      count2 = (n + 10*y*z + (x + 10*y) - 1) / (x + 10*y);
  Это безопаснее и не зависит от точности double.
- Оба варианта (с ИИ и без) сравниваются напрямую,
  выбирается минимальный.
